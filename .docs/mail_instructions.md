# Инструкция для администратора: настройка почты в приложении

Эта инструкция поможет вам настроить почтовый ящик, с которого приложение будет автоматически отправлять уведомления о новых заявках. Управление почтой доступно только пользователям с ролью **Администратор**.

---

## Демонстрационные настройки

При первой миграции база получает эти исходные значения, только если настройки почты еще не заданы:

* **Базовый почтовый ящик:** `sender@example.com` (адрес отправителя)
* **Пароль:** `test-password-123` (для MailPit подойдет любой пароль; это не настоящий App Password)
* **Целевой почтовый ящик:** `recipient@example.com` (получатель уведомлений)

Для локальной демонстрации укажите в настройках SMTP хост `localhost`, порт `1025`, отключите авторизацию и SSL. При отключенном SSL используется STARTTLS, если SMTP-сервер его поддерживает. При старте backend сохраняет адреса и пароль в БД в зашифрованном виде; SMTP-параметры хранятся без шифрования. Миграция задает демонстрационные параметры только при добавлении полей и не меняет уже существующие адреса и пароль.

---

## Дефолтные настройки SMTP для популярных почтовых провайдеров

Ниже приведены стандартные хосты и порты для настройки отправки почты. Для большинства современных сервисов **обязательно использование шифрования** (SSL или STARTTLS) и **пароля приложения**, а не основного пароля от аккаунта.

**Международные провайдеры**

| Провайдер | SMTP Хост | Порт (SSL) | Порт (STARTTLS) | Примечание |
| :--- | :--- | :--- | :--- | :--- |
| **Gmail** | `smtp.gmail.com` | **465** | **587** | Требуется App Password (при включенной 2FA). Порт 25 обычно заблокирован. |
| **Outlook / Hotmail** | `smtp-mail.outlook.com` | — | **587** | Используется STARTTLS. Для Office 365 хост: `smtp.office365.com`. |
| **Yahoo Mail** | `smtp.mail.yahoo.com` | **465** | **587** | Требуется пароль приложения. |
| **iCloud Mail** | `smtp.mail.me.com` | — | **587** | Apple рекомендует именно 587. Требуется пароль приложения. |
| **Zoho Mail** | `smtp.zoho.com` | **465** | **587** | Для аккаунтов с личным доменом: `smtppro.zoho.com`. |
| **AOL Mail** | `smtp.aol.com` | **465** | **587** | Требуется пароль приложения. |

**Российские провайдеры**

| Провайдер | SMTP Хост | Порт (SSL) | Порт (STARTTLS) | Примечание |
| :--- | :--- | :--- | :--- | :--- |
| **Яндекс.Почта** | `smtp.yandex.ru` (или `.com`) | **465** | **587** | Требуется пароль приложения. Порт 465 с SSL — самый надежный вариант. |
| **Mail.ru** | `smtp.mail.ru` | **465** | **587** | Требуется пароль для внешних приложений. |

**Важные замечания**

1. **Порт 465 (SSL) vs 587 (STARTTLS)**: При выборе порта 465 **обязательно** ставьте галочку «Использовать SSL». Если выбираете 587 — галочку SSL нужно снять (будет использован STARTTLS).
2. **Пароли**: Везде, где указано «Требуется пароль приложения», обычный пароль от почты не подойдет. Это частая причина ошибки `Authentication failed`.
3. **Локальный тест**: Для Mailpit (в Docker) используйте хост `localhost` (или имя контейнера) и порт **1025**, без SSL и авторизации.

## 2. Где взять пароль (Пароль приложения)

**Никогда не используйте основной пароль от своей почты.** Приложение требует специальный **«Пароль приложения»** (App Password). Это одноразовый 16-значный код, который генерируется в настройках безопасности вашего почтового провайдера.

Вот как его получить для популярных сервисов:

### Для Gmail
1. Убедитесь, что в вашем Google-аккаунте включена **двухэтапная аутентификация**.
2. Перейдите по адресу `myaccount.google.com/apppasswords`.
3. Введите название (например, "Заявки SMTP") и нажмите «Создать».
4. Скопируйте появившийся 16-значный код. **Он показывается только один раз**. Если Google отображает код группами с пробелами, приложение удалит пробелы при сохранении.

### Для Яндекс.Почты
1. Зайдите в настройки Яндекс ID → «Безопасность» → «Пароли приложений».
2. Нажмите «Создать пароль».
3. Выберите тип приложения **«Почта»**.
4. Скопируйте сгенерированный пароль (он показывается один раз).

### Для Mail.ru
1. Перейдите в «Настройки» → «Безопасность» → «Пароли для внешних приложений».
2. Создайте новый пароль.
3. Рекомендуется выбрать опцию **«Только отправка писем»**, чтобы ограничить права доступа.

## 3. Как установить почту (первичная настройка)

1. Войдите в приложение под учетной записью **Администратора**.
2. Откройте раздел **«Настройки» (Settings)**.
3. Найдите блок **«Настройки почты»**.
4. Заполните поля:
   * **Базовый почтовый ящик:** Адрес, с которого будут уходить письма (например, `my-company@gmail.com`). Это поле также будет отображаться в письме как «От кого» (From).
   * **Пароль:** Вставьте 16-значный «Пароль приложения», который вы сгенерировали в шаге 2. Пробелы в скопированном пароле будут удалены автоматически. **Не вводите сюда свой обычный пароль от почты.**
   * **Целевой почтовый ящик:** Адрес, **куда** будут приходить письма о новых заявках. Это может быть тот же адрес или адрес менеджера/отдела.
   * **SMTP хост и порт:** Адрес SMTP-сервера и его порт (для Gmail обычно `smtp.gmail.com` и `587`; для MailPit — `localhost` и `1025`).
   * **Требуется авторизация:** Включите для почтового провайдера, который требует логин и пароль.
   * **Использовать SSL:** Включите для implicit SSL (обычно порт `465`). Если выключено, отправка использует STARTTLS, когда сервер его поддерживает.
5. Нажмите **«Сохранить» (Save)**.

После сохранения поля будут заблокированы: адреса останутся видны, а пароль будет показан маской (`••••••••`). В целях безопасности приложение не позволяет просмотреть сохраненный пароль обратно.

---

## 4. Как изменить почту или пароль

Чтобы изменить настройки, переключите значок блокировки в тулбаре. При смене адреса отправителя приложение запросит подтверждение сброса пароля; после подтверждения введите новый пароль приложения. При изменении только адреса получателя пароль можно оставить пустым — сохраненный пароль останется прежним. После сохранения поля снова будут заблокированы. Значок блокировки можно переключать в любой момент, чтобы временно заблокировать или разблокировать поля.

Изменения вступают в силу **сразу**. Перезапуск приложения не требуется. Следующее созданное письмо уйдет уже с новыми настройками.

---

## 5. Как проверить, что всё работает

1. Убедитесь, что настройки сохранены.
2. Создайте тестовую заявку в приложении (от лица любого пользователя).
3. Проверьте почтовый ящик, указанный в поле **Целевой почтовый ящик**.
4. Вы должны получить письмо с темой «Создана новая заявка» и данными о том, кто её создал.

> **Если письмо не пришло:** Проверьте папку «Спам». Если писем нет, проверьте правильность введенного «Пароля приложения» или обратитесь к разработчику для проверки логов сервера.
